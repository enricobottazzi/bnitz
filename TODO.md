# Body highlighting

- [x] **Define `.bnitz` v3arxiv.** V3 (`version: 3`) is the current general-purpose format used by the standalone Reader and Playground. The extension and Worker use v3arxiv (`version: "3arxiv"`) for maps tied to an arXiv revision. Store `arxivId` (for example, `1706.03762v7`), `nucleus`, and `spans`. Each highlight has `{section, start, end}`, with offsets relative to the extracted `abstract` or `body` of that revision. Keep each planet’s own `start` and `end` as its abstract anchor. Get the title, authors, and text from the paper.
- [x] **Use one Worker request and one cache entry per arXiv revision.** Replace `/v1/abstract-map` with `/v1/paper-map`. Chrome sends the extracted `paper.json` once. Use `arxivId` as the key and the complete, validated v3arxiv `paper.bnitz` as the value. Keep a fingerprint of the extracted abstract and body in cache metadata so a hit requires the same text the offsets were computed against. On a miss, run Steps 2 and 3 and store the result. Remove the old abstract graph cache.
- [x] **Step 2 · Produce and validate `abstract_map.json`.** Keep it in Worker memory for Step 3. Check that its arXiv ID matches the request, that planet IDs are unique, that every planet leads to one nucleus without cycles, and that each anchor and highlight is valid against the extracted abstract in `paper.json`.
- [x] **Step 3 · Produce `paper.bnitz`.** Run the [body passage recipe](extension/worker/recipes.mjs) with the [worked example](extension/worker/body-passage-examples.json), then the planet IDs, relations, abstract highlights, and all extracted body blocks in order from the same revision. Verify that each proposed highlight occurs exactly once in its named block, discard invalid or duplicate matches, and compute body offsets from the extracted text. Tag the abstract and body ranges when assembling v3arxiv. On a passage generation error, return the validated abstract map for display and report the error.
- [x] **Step 4 · Show the selected planet’s highlights.** Match the map’s versioned arXiv ID to the open page and reuse the page’s extracted text and DOM offsets. Send only the selected planet’s ranges to the content script. Paint the ranges in the abstract and body and show their positions on one right-edge tracker for manual scrolling. Use the existing export control to download the completed `paper.bnitz`.
- [x] **Document and verify.** Update the pipeline in the [extension README](extension/README.md) and explain in the [privacy policy](extension/PRIVACY.md) what the Worker caches and what it sends to OpenRouter. Build the extension and Worker. Verify that existing v3 maps still open, malformed intermediate maps are rejected, a cache hit skips generation, and changed text triggers regeneration. Smoke-test highlight verification, tracker positions, and v3arxiv export on an arXiv HTML page.
